# 학교 축제 PC방 운영 시스템 설계

## 목적과 범위

학교 축제에서 키오스크로 좌석을 배정하고, Windows 노트북에서 게임·이용 시간·축제 머니·간식 주문을 통합 관리한다. 현재 저장소에는 README만 있다. 이번 작업은 서버, 웹 키오스크·관리자, Windows Electron 런처를 포함하는 하나의 프로젝트다.

사용자가 선택한 방식은 Electron 기반 앱과 중앙 서버다. 런처는 전체 화면으로 실행되며 현장 관리자 비밀번호 또는 관리자 화면의 원격 승인으로 종료한다. Windows 계정·운영체제 잠금은 범위에 포함하지 않는다. 작업 관리자, Windows 단축키, 전원 조작을 통한 우회까지 차단한다고 보장하지 않는다.

## 검토한 접근

- Electron + 중앙 서버: 화면과 타입을 공유할 수 있어 행사 요구 변경에 유리하다. 메모리와 배포 크기가 크다. 사용자가 이 방식을 선택했다.
- C# 런처 + 웹 화면 + 서버: Windows 제어에 유리하지만 기술과 화면 구현이 나뉜다.
- 웹만 사용: 로컬 게임 실행·종료 및 데스크톱 메뉴 제어 요구를 만족하기 어려워 제외했다.

## 제안한 기술과 배치

아래 세부 선택은 구현자의 제안이며 사용자 지정 사항은 아니다.

- TypeScript, React 기반 화면, Node.js 서버, SQLite 영속 저장, WebSocket 상태 알림을 사용한다.
- 서버 한 대와 키오스크·사용자 PC를 같은 행사장 내부 네트워크에 연결한다. 핵심 기능은 외부 인터넷 없이 동작한다. 개별 게임의 인터넷·로그인 요구는 별도다.
- 서버는 Windows 또는 Linux에서 실행한다. 웹 키오스크와 관리자 화면은 브라우저에서 열고, 사용자 PC에는 Windows Electron 앱을 설치한다.
- 서버가 좌석, 세션, 잔액, 주문의 원본이다. 클라이언트 시계나 화면 표시를 결제 판단에 사용하지 않는다.

## 이용 흐름

1. 키오스크에서 빈자리 선택 후 이름과 학번을 입력한다. 추가 연락처는 수집하지 않는 것을 기본으로 제안한다.
2. 서버가 좌석 확보와 이용권 생성을 한 트랜잭션으로 처리한다. 초기 시간·머니는 관리자 설정을 따른다. 중복 터치와 재전송은 중복 지급하지 않는다.
3. 키오스크가 추측하기 어려운 일회용 로그인 번호를 보여준다. 배정된 PC에서만 번호를 사용할 수 있고, 로그인 시도 횟수를 제한한다. 배정 후 로그인 유효 시간은 설정 가능하며 만료 시 미사용 배정을 해제한다.
4. PC에서 로그인에 성공한 시점부터 서버 기준 종료 시각까지 시간이 흐른다. 동일 이용권의 동시 로그인은 막는다. 앱 재시작으로 시간이 초기화되지 않는다.
5. 게임 목록에서 설치된 게임을 선택한다. 게임 변경은 기존에 런처가 실행한 게임을 종료한 후 새 게임을 실행한다. 종료 시 저장되지 않은 진행이 사라질 수 있음을 화면에 알린다.
6. 시간 만료 또는 관리자 이용 종료 시 런처가 실행한 게임 프로세스를 종료하고 로그인 화면으로 돌아간다. 이용 종료는 Windows 종료와 별개다.

## 화면과 기능

### 키오스크

좌석 배치·사용 상태, 인적사항 입력, 초기 지급 내용, 로그인 번호를 제공한다. 빈자리·배정 대기·사용 중·오프라인·관리자 사용 중지 상태를 구분한다. 다른 사람의 이름·학번이나 기존 로그인 번호는 표시하지 않는다.

### Windows 런처

- 좌석별 기기 등록 후 전체 화면 로그인과 게임 목록을 제공한다. 일반 종료·Alt+F4는 승인 절차로 연결한다.
- 화면 오른쪽 위에 약 1초간 마우스를 두면 남은 시간·머니·간식 주문·시간 연장·게임 변경·종료 요청 메뉴를 연다. 마우스 감지와 메뉴 창은 게임이 포커스를 가진 동안에도 작동하도록 구현한다.
- 게임은 관리자에게 등록된 로컬 실행 파일과 인수로만 시작한다. 서버 명령으로 임의 셸 명령을 실행하지 않는다. 게임 경로는 PC별로 설정 가능하다.
- 테두리 없는 창 또는 창 모드 게임을 우선 지원한다. 독점 전체 화면, 관리자 권한, 안티치트가 있는 게임의 메뉴 표시·종료는 실제 Windows 검증 대상이며 보편적 호환을 약속하지 않는다.
- 종료 승인과 이용 종료를 구분한다. 승인된 런처 종료 시 활성 게임을 닫고 세션을 종료한다. 재시작 시 서버 상태에 따라 로그인 화면으로 복구한다.

### 주문·시간 연장

- 머니는 축제용 포인트이며 실제 결제·충전 서비스는 포함하지 않는다.
- 관리자가 상품·가격·재고와 연장 시간·가격을 설정한다. 간식은 즉시 잔액과 재고를 차감하고 주문 접수→준비→전달 상태로 관리한다.
- 주문 취소·환불은 관리자만 할 수 있다. 취소 시 재고와 머니는 정확히 한 번 복구한다. 연장은 서버가 잔액 차감과 종료 시각 변경을 원자적으로 처리한다.
- 잔액 부족, 품절, 종료된 세션은 구매할 수 없다. 중복 요청 방지를 적용한다.

### 관리자

- 관리자 로그인 후 좌석 상태, 잔여 시간·머니, 기기 연결 상태, 주문, 종료 승인 요청을 실시간 확인한다.
- 시간·머니 추가 및 차감, 세션 종료, 좌석 사용 중지, 초기 지급 정책, 게임·상품·연장 상품 설정을 제공한다. 차감으로 잔액을 음수로 만들지 않는다.
- 현장 비밀번호로 런처를 종료하거나, 관리자가 원격 요청을 승인·거절할 수 있다. 원격 요청에는 기기·좌석과 요청 유효 시간을 묶으며 지난 승인을 재사용할 수 없다.
- '이용 종료'와 'Windows 종료'를 별도 버튼으로 표시한다. Windows 종료는 관리자 확인 후 연결된 기기에 전달하고 응답·실패를 기록한다. 전원이 꺼졌다는 확인 없이 성공으로 표시하지 않는다.
- 금전·시간 변경, 주문 취소, 종료 승인, 원격 명령을 감사 기록으로 남긴다. 이름·학번은 관리자만 보고, 행사 종료 후 삭제 기능을 제공한다.

## 인증과 장애 처리

- 첫 서버 실행 시 관리자가 비밀번호를 설정한다. 고정 기본 비밀번호를 배포하지 않고 해시로 보관한다. PC는 일회성 등록 코드로 등록하고 좌석과 연결된 기기 자격 증명을 사용한다.
- Electron은 renderer의 Node 접근을 끄고 context isolation과 제한된 IPC를 사용한다. 관리자 권한·머니·종료 승인 판단은 서버 또는 신뢰된 main 프로세스에서 수행한다.
- 현장 종료 비밀번호는 온라인일 때 서버에서 검증한다. 네트워크 장애 시에도 운영자가 빠져나올 수 있도록 기기별 비상 종료 코드를 등록 때 생성해 관리자가 별도로 보관한다. 로컬에는 해시만 보관하고 시도 횟수를 제한한다. 이는 시스템 잠금 우회 방지 수단은 아니다.
- LAN에서도 로그인·관리자·기기 통신은 TLS로 보호한다. 설치·운영 안내에 서버 주소와 인증서 신뢰 설정을 포함하며 인증서 검증을 끄지 않는다.
- 연결이 끊기면 구매·연장·신규 로그인·원격 승인을 중지하고 연결 상태를 표시한다. 이미 로그인한 기기는 마지막으로 확인한 종료 시각까지 단조 시계를 사용해 남은 시간을 계산한다. 종료 시각에 게임을 닫는다. 앱 재실행 상태에서 서버가 없으면 로그인시키지 않는다.
- 서버 재시작 후 세션과 주문을 DB에서 복원한다. 기기는 재연결 후 상태를 동기화하며 지난 원격 명령을 중복 실행하지 않는다. 기기 오프라인 상태는 원격 종료 성공과 구분한다.

## 검증과 완료 기준

- 서버 자동 테스트: 좌석 동시 배정, 로그인 시간 시작, 재시작 복원, 중복 구매·환불·연장 방지, 잔액·재고 부족, 권한 분리, 승인 만료.
- 웹 통합 검증: 키오스크 배정→PC 로그인→상품 주문·연장→관리자 처리→세션 만료 흐름을 실행한다.
- Windows 실제 검증: 설치·실행, 게임 실행·전환·프로세스 종료, 게임 중 오른쪽 위 메뉴, Alt+F4 승인, 현장/원격 승인, 비상 종료, 연결 단절, Windows 종료를 확인한다.
- 현재 클라우드 Linux에서 가능한 서버·웹·Electron 빌드 검사와 실제 Windows 노트북에서 해야 하는 검증 결과를 분리해 보고한다. Windows 검증 전에는 런처의 현장 동작 완료를 주장하지 않는다.
- 실행 안내, 설정 예시, Windows 배포물 생성 방법, 행사 전 점검 및 복구 절차를 제공한다. 실제 게임·상용 게임 계정·라이선스는 배포물에 포함하지 않는다.

## 구현자가 정할 세부 사항

패키지 구성, API 경로, UI 배치·색상, 로그인 번호 길이와 제한값, 요청 만료값, 초기 예시 상품은 구현자가 정하되 운영값은 설정 가능하게 한다. 시간·머니 초기값, PC 수, 실제 게임 경로는 설치 후 관리자 설정으로 입력한다. 실제 노트북과 게임을 확보한 뒤 게임별 호환성을 검증한다.

## 승인된 화면 스타일 변경

사용자 추가 요청: 블랙톤 대신 화이트톤과 나이키 볼트 계열 네온 라임 강조색을 사용한다. 화면 구조와 기능은 유지하고 흰 표면, 짙은 글자, 네온 라임 버튼·선택 표시로 구성한다.

추가 사용자 지정: 둥근모꼴(RoundedFixedsys)을 본문·수치에, 양진체(Yangjin)를 제목에 사용해 90년대 PC방 분위기를 만든다. 두 폰트는 로컬 배포물에 포함하고 화이트·네온 라임 색상은 유지한다.
