# Supabase 클라우드 전환

사용자 요청으로 로컬 서버를 Supabase Auth·Postgres RPC·Realtime으로 대체한다. 관리자 웹은 GitHub Pages에 공개하고, Windows 런처는 직접 HTTPS로 Supabase에 연결한다. 다른 Node 호스팅을 추가하는 방식도 가능하지만 사용자가 Supabase를 지정했고 폰 접속과 별도 서버 제거가 목적이므로 Supabase 직접 백엔드가 적합하다.

- 프로젝트: https://gtvgeqdxcoiplhhufvgg.supabase.co. 제공된 publishable 키는 공개 클라이언트 설정이며 관리자 권한을 부여하지 않는다.
- 내부 상태는 RLS로 직접 조회를 막고 SECURITY DEFINER RPC에서 관리자/기기 권한, 트랜잭션, 멱등성을 확인한다. 기기는 좌석별 별도 토큰을 사용한다. Realtime에는 변경 신호만 공개한다.
- Supabase Auth 관리자 계정별 로그인·비밀번호. 소유자가 계정을 만들고 개별 권한·활성 상태를 설정한다. 계정 생성·비밀번호 재설정은 Edge Function의 서버 전용 Auth Admin API로 처리한다. 마지막 소유자 비활성화 금지.
- 앱 종료 승인용 비밀번호도 여러 개 추가·폐기 가능하며 해시만 저장한다. 계정 권한과 종료 승인 코드를 구분한다.
- 폰 브라우저에서 좌석·잔여 시간·주문을 보고 권한에 따라 시간/머니 조정, 킥, PC 종료와 종료 요청 승인을 수행한다.
- 라이트·다크·시스템 모드. 둥근모꼴을 제목·본문·수치에 폭넓게 쓰고 양진체는 서비스 로고/큰 제목에만 쓴다.
- 운영 설정에서 서비스명, 부제, 로고, 기본 테마를 변경한다. 로고는 제한된 이미지 형식·크기로 Supabase Storage에 저장한다.
- 게임 오류는 실행 이전의 경로 형식/파일 존재 확인에서 발생한다. 실제 학생 PC 파일은 이 환경에서 볼 수 없다. 운영자 인증 뒤 해당 PC 파일 선택기로 .exe를 지정하고 PC별 로컬 경로를 우선 사용한다. 따옴표·환경 변수·UNC 경로를 정규화하고 구체적인 경로 오류를 표시한다.
- SQL 마이그레이션/최초 소유자 설정 파일, Edge Function 파일, 배포 안내를 별도 제공한다. 기존 SQLite 데이터 자동 이전은 하지 않고 신/구 데이터가 섞이지 않도록 클라우드 기기를 새로 등록한다.
- 프로젝트 SQL 설치와 Edge Function 배포는 사용자가 수행해야 한다. 공개 키만으로 프로젝트 관리 설정을 대신 실행할 수 없다. 설치 전 클라우드 준비 완료를 주장하지 않는다.

기존 사용자의 비용 절약 요청을 유지한다. 전체 테스트·브라우저 점검·독립 검토를 반복하지 않으며 컴파일/패키징에 필요한 확인만 한다. 구현 및 GitHub 게시 방식은 기존 직접 실행·업로드 요청을 유지한다.

추가 요청 반영: 주문은 앱 안 확인 팝업, 등록된 Station의 Alt+F4 전역 차단과 관리자 알림, 4~6자리 학생 비밀번호, 배정 시 로그인 화면 자동 전환, 입장 시 타이머, 만료 시 감사 잠금 화면과 전용 대기 화면. 공개 클라우드의 좌석 배정은 등록된 키오스크만 허용한다. 기본 Electron 아이콘은 레트로 CRT 이미지로 교체하며 EXE·바로가기 리소스를 Windows에서 편집해 게시한다.
