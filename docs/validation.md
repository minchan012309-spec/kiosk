# 전달 상태와 검증 기록

## 구현 및 확인

- 중앙 서버, 관리자·키오스크, Windows용 Electron 런처 구현.
- 화이트·네온 라임과 둥근모꼴/양진체를 사용한 레트로 화면. 폰트 파일을 로컬 배포물에 포함.
- 자동 테스트 24개 통과: 좌석·시간·머니·주문·환불·인증·복구·동시 수정·재전송 규칙.
- 실제 Chromium 통합 흐름 통과: 발급→로그인→구매→머니 조정의 응답 유실 후 재시도→주문 처리→원격 승인.
- 실제 Electron 서버 테스트 통과: TLS, 포함된 SQLite, 첫 관리자 설정, 좌석 생성, 관리자 인증이 없는 별도 키오스크 창.
- 실제 Electron 런처 테스트 통과: 연결 파일, 등록, Linux libsecret 암호화 저장, 재시작 복원, 로그인·간식·연장, 원격 승인, 오프라인 비상 종료, 다음 접속 시 정확한 이전 세션 종료.
- Windows 배포용 app.asar를 Linux Electron의 패키지 실행 경로에 넣은 테스트에서도 서버 설정·키오스크와 인증 경계를 확인. 이는 Windows 설치 실행 검증을 대체하지 않음.
- 타입 검사 및 포맷 검사 통과.

독립 코드 검토에서 발견한 관리자 URL 인코딩 인증 우회, 종료 재시도 누락, 응답 유실 후 중복 지급, 캐시 개인정보 잔존, 비상 종료 세션 복구, 상품 편집 시 재고 되돌림을 재현 테스트로 확인하고 수정했다. 수정 전 실패와 수정 후 통과를 확인했다.

## 아직 확인하지 않은 범위

실제 Windows 설치·제거, Windows DPAPI, 개별 게임 실행과 자식 프로세스 종료, 게임 위 메뉴, 다중 모니터/배율, OS 종료는 실제 행사 노트북에서 점검해야 한다. 설치 파일은 미서명 상태다. [Windows 점검표](windows-checklist.md)를 사용한다.

## 구현하면서 정한 사항

- 기존 클라우드 격리 체크아웃과 work 브랜치를 유지했다. 구현 단계에서는 추가 worktree와 병합을 수행하지 않았다. 이후 사용자 요청으로 GitHub main에 소스를 올리고 설치 ZIP을 v1.0.0 릴리스에 게시했다.
- 별도 Node.js 설치가 필요 없도록 서버도 EXE로 제공한다. 서버와 각 사용자 PC에서 첫 연결 설정은 필요하다.
- SQLite의 한 상태 문서를 트랜잭션으로 저장한다. 학교 축제 규모를 위한 선택이며 대규모 운영에서는 조회 성능과 DB 구조를 재검토해야 한다.
- 공개 인증서 연결 파일을 한 번 복사해 TLS를 검증한다. 네트워크/IP 변경 시 재설정이 필요할 수 있다.
- NSIS의 설치 시점 제거 프로그램 생성을 사용한다. 서명 인증서는 제공되지 않아 Windows 게시자 확인 메시지가 나올 수 있다.
- 설치 프로그램 압축은 zlib를 사용한다. 중복 압축 시간을 줄이며 다운로드 파일 크기는 더 크다. 런타임 기능에는 영향이 없다.
- 전체 화면 앱이므로 Windows 시스템 단축키나 로컬 사용자 변조를 차단하지 않는다.
- 별도 부트스트랩 실행 파일이 종료된 뒤 게임을 분리 실행하는 경우는 게임별 확인이 필요하다. 추적되지 않는 프로세스가 남을 수 있다.

클라우드 스킬의 보조 셸 스크립트 리소스를 읽을 수 없어 작업 기록은 직접 유지했다. 제품 동작에는 영향이 없다. 검증되지 않은 Windows 항목을 통과로 표시하지 않는다.
