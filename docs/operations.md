# 설치와 행사 운영 안내

## 역할과 배치

서버 설치 프로그램은 중앙 DB와 HTTPS 서버, 관리자 화면, 별도 키오스크 창을 함께 실행합니다. 사용자 PC에는 Station 설치 프로그램만 필요합니다. 모든 통신은 행사장 내부 네트워크로 처리되며 게임 자체의 인터넷 요구는 별개입니다. 서버 PC는 행사 내내 켜 두고 절전·덮개 닫기 자동 절전을 해제하세요.

서버 기본 주소는 `https://서버IPv4:8443`입니다. 공유기의 DHCP 예약으로 서버 IP를 고정하는 것을 권장합니다. Windows 네트워크를 개인 네트워크로 설정하고 서버 앱의 TCP 8443 수신을 허용하세요. 공개 인터넷 포트 개방은 필요하지 않습니다. 학교 게스트 Wi-Fi의 기기 격리 기능은 서버 연결을 막을 수 있습니다.

## 첫 실행과 연결 파일

서버는 첫 실행에서 인증서, 개인키, 초기 설정 코드, SQLite DB를 생성합니다. 서버 창에서는 초기 코드가 자동 입력되며 관리자 비밀번호를 10자 이상으로 설정합니다. 고정 기본 비밀번호는 없습니다. 웹 브라우저로 최초 설정을 한다면 서버 데이터 폴더의 `setup-token` 값을 서버 운영자가 직접 입력해야 합니다. 채팅이나 학생에게 공유하지 마세요.

운영 설정에서 저장한 `.pcclub` 파일은 공개 인증서와 서버 주소만 포함합니다. 사용자 PC는 이 인증서를 신뢰하고 주소·서명·유효기간을 검증합니다. 인증서 경고 무시나 TLS 검사 해제는 사용하지 않습니다. 복사한 파일에서 주소나 인증서를 임의 수정하지 마세요.

서버의 현재 IP가 인증서에 포함되지 않아 연결 파일을 내보내지 못하면 행사 전에 네트워크를 확정하세요. IP를 변경해야 한다면 운영을 중단하고 서버를 종료한 뒤 데이터 폴더의 `server.crt`와 `server.key`를 안전하게 별도 보관하고 원본을 제거하여 다음 시작에 재발급합니다. 모든 PC를 새 연결 파일로 다시 등록해야 하므로 **진행 중에 하지 마세요**. 기존 DB는 유지됩니다. 재등록 전에 각 PC를 현장/원격 승인으로 종료하고 `station.json`을 별도 보관한 뒤 제거합니다. 비상 코드는 새로 발급됩니다.

PC 등록 코드는 10분 후 만료되며 한 번만 사용할 수 있습니다. 사용 중인 좌석은 재등록할 수 없습니다. 등록된 PC에서만 해당 좌석의 학생 로그인이 가능합니다. 등록 시 표시되는 기기별 비상 코드는 운영자만 보관하고 학생에게 보여 주지 마세요. 기기 토큰은 Windows 사용자의 보안 저장소(DPAPI)로 암호화됩니다.

서버의 키오스크 창은 관리자와 별도 브라우저 세션을 사용하며 관리자 로그인 쿠키나 데스크톱 제어 bridge를 공유하지 않습니다.

## 게임 등록

게임 관리에서 게임 이름, 설명, 실제 Windows 실행 파일, 인수를 설정합니다. 인수는 `[]` 또는 `["--windowed"]` 같은 JSON 배열로 입력합니다. 셸 문자열·바로가기·배치 파일을 실행하지 않습니다. 공통 경로를 지정하거나 PC별 경로에 `{"좌석 UUID":"C:\\Games\\Game\\game.exe"}` 형식으로 입력할 수 있습니다. 좌석 ID는 게임 관리 화면에서 확인합니다.

게임은 실제 노트북에서 먼저 설치하고 업데이트·로그인까지 마쳐 두세요. 관리자 권한이 필요한 게임이나 별도 런처가 실행 파일을 대신 실행한 뒤 종료하는 게임은 관리 대상 프로세스 추적이 제한될 수 있습니다. 직접 실행 가능한 게임 파일을 우선 사용하고 각 게임의 종료 동작을 확인하세요. Steam·상용 게임 파일과 계정은 배포물에 포함하지 않습니다.

게임 전환과 이용 만료는 현재 게임 프로세스를 강제 종료할 수 있습니다. 학생에게 진행 내용이 저장되지 않을 수 있음을 안내하세요. 창 모드 또는 테두리 없는 창 모드가 오른쪽 위 메뉴와 호환성이 좋습니다. 독점 전체 화면·안티치트·별도 권한으로 실행되는 게임은 실기 확인이 필요합니다.

## 시간·머니·주문

머니는 실제 화폐가 아닌 행사 포인트입니다. 초기 지급 설정은 이후 발급하는 이용권부터 반영됩니다. 시간은 PC 로그인 시 시작하며 앱 재시작으로 초기화되지 않습니다. 기본 배정 유효 시간은 5분입니다. 시간 연장은 결제와 동시에 종료 시각에 반영됩니다. 수동 조정은 추가를 양수, 차감을 음수로 입력합니다.

간식 주문은 접수→준비 중→전달 완료 순서입니다. 취소는 관리자만 가능하며 머니와 재고를 한 번만 복구합니다. 종료된 세션에 대한 환불도 기록되지만 종료된 이용권을 다시 활성화하지는 않습니다. 주문 재전송은 같은 요청 번호로 처리되어 중복 결제를 막습니다.

## 프로그램 종료와 PC 종료

학생의 Alt+F4 및 창 닫기는 일반 종료 대신 관리자 승인 메뉴로 연결됩니다. 온라인일 때 현장 비밀번호 검증 또는 관리자 화면의 원격 승인으로 런처를 종료합니다. 네트워크 장애 시 기기별 비상 종료 코드를 사용할 수 있으며 잘못된 입력 5회 후 5분간 제한됩니다.

관리자의 **이용 종료**는 이용 세션과 게임을 종료하고 PC를 로그인 화면으로 돌립니다. **Windows 종료**는 별도 확인 후 OS 종료 명령을 보냅니다. 서버에 'PC가 명령 접수'로 표시되어도 실제 전원이 꺼진 것을 확인했다는 뜻은 아닙니다. 실패·만료는 구분해 표시합니다. 원격 명령은 기기에 귀속되고 만료·중복 실행을 제한합니다.

전체 화면 앱은 Windows 잠금 기능이 아닙니다. Ctrl+Alt+Delete, 작업 관리자, 전원 조작 등을 통한 운영체제 접근은 막지 않습니다.

## 연결 장애

연결이 끊기면 신규 로그인·주문·연장·원격 승인을 중지합니다. 로그인 중이던 PC는 마지막 확인한 종료 시각까지 단조 시계로 시간을 계산하고 만료 시 게임을 닫습니다. 끊긴 상태에서 런처를 다시 시작하면 새 로그인은 허용하지 않습니다. 서버 복구 후 자동 재연결하며 DB에 저장된 세션·주문을 다시 조회합니다.

서버가 잠자기 상태로 들어가거나 네트워크가 바뀌지 않았는지 먼저 확인하세요. 런처 연결 파일과 서버 IP, 방화벽, Wi-Fi의 기기 격리 설정을 확인합니다. 인증서가 다르다는 오류를 단순 무시하지 마세요.

## 데이터·백업·비밀번호 복구

Windows 저장 위치:

- 서버: `%APPDATA%\PCClub\server\server\`
- 사용자 PC 설정: `%APPDATA%\PCClub\station\station.json`
- 명령 중복 방지 기록: `%APPDATA%\PCClub\station\command-state.json`

서버 데이터 폴더에는 `festival.sqlite`, 인증서·개인키, 초기 코드가 있습니다. **서버를 정상 종료한 뒤 폴더 전체를 복사**해 백업합니다. 실행 중 SQLite 파일 하나만 복사하지 마세요(WAL에 최신 정보가 있을 수 있습니다). 복원도 서버가 꺼진 상태에서 폴더 전체로 수행합니다. 두 서버를 동시에 같은 기기와 운영하지 마세요.

비밀번호를 잊었으면 서버 EXE의 로그인 화면에서 **관리자 비밀번호를 잊으셨나요?**를 누르고 서버 PC에서 확인합니다. 좌석·세션·머니·주문은 보존하고 관리자 로그인과 비밀번호만 초기화합니다. 이 기능은 원격 웹 API로 제공하지 않습니다. 서버 노트북은 운영자만 접근하도록 관리하세요.

행사 종료 후 관리자에서 진행 중 세션을 종료하고 개인정보 삭제를 실행합니다. 종료된 이용자의 이름·학번은 제거되고 회계·주문 기록은 유지됩니다. 백업본에는 이전 개인정보가 남을 수 있으므로 보관 기한을 정해 함께 삭제하세요. 프로그램 제거는 재설치 복구를 위해 사용자 데이터 폴더를 지우지 않습니다.

## 빌드와 배포

`npm ci && npm run build && npm run dist:win`으로 설치 파일을 생성합니다. Electron과 서버 의존성을 묶으므로 행사 노트북에 별도 Node.js가 필요하지 않습니다. 설치 파일은 사용자 계정 범위에 설치하고 바탕화면·시작 메뉴 바로가기와 제거 프로그램을 등록합니다. 기존 임의 파일이 있는 폴더에는 설치하지 않습니다.

현재 설치 파일은 서명되지 않았습니다. Windows의 게시자 확인 메시지가 뜰 수 있습니다. 배포 시 `SHA256SUMS.txt`와 함께 전달하세요. 실제 Windows 검증은 `windows-checklist.md`에 결과를 적습니다. 소스/클라우드 테스트 성공을 Windows 게임 호환성 성공으로 간주하지 않습니다.
